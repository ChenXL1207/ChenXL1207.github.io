C++缓存系统项目

背景介绍

什么是缓存？

缓存是将高频访问的数据暂存到内存中，是加速数据访问的存储，降低延迟，提高吞吐率的利器。

为什么要实现缓存系统?

因缓存的使用相关需求，通过牺牲一部分服务器内存，减少对磁盘或者数据库资源进行直接读写，可换取更快响应速度，尤其是处理高并发的场景，负责存储经常访问的数据，通过设计合理的缓存机制提高资源的访问效率。由于服务器的内存是有限的，我们不能把所有数据都存放在内存中，因此需要一种机制来决定当使用内存超过一定标准时，应该删除哪些数据，这就涉及到缓存淘汰策略的选择。

在什么地方加缓存？

缓存对于每个开发者来说是相当熟悉了，为了提高程序的性能我们会去加缓存，但是在什么地方加缓存，如何加缓存呢？举个例子：假设一个网站，需要提高性能，缓存可以放在浏览器，可以放在反向代理服务器，还可以放在应用程序进程内，同时可以放在分布式缓存系统中。

从用户请求数据到数据返回，数据经过了浏览器、CDN、代理服务器、应用服务器，以及数据库各个环节。每个环节都可以运用缓存技术。从浏览器/客户端开始请求数据，通过HTTP配合CDN获取数据的变更情况，到达代理服务器(Nginx)可以通过反向代理获取静态资源。再往下来到应用服务器可以通过进程内（堆内）缓存，分布式缓存等方式获取数据。如果以上所有缓存都没有命中数据，才会回源到数据库。

缓存的顺序：用户请求->HTTP缓存->CDN缓存->代理服务器缓存->进程内缓存->分布式缓存->数据库

距离用户越近，缓存能够发挥的效果越好。

FIFO缓存技术（先进后出）

先进先出算法，是最简单的页面替换策略，按照页面进入内存的顺序来决定替换哪个页面。即优先淘汰最早进入内存的页面，不论这些页面之后是否被频繁访问。但是FIFO可能会导致“Belady异常”，即随着分配给进程的物理块数增加，缺页次数反而增加。

  • FIFO 完全按照页面进入内存的时间替换，与“未来是否还会访问”无关。
  • 当物理块增加时，旧页面的生命周期可能被延长，导致新访问的页面更早把常用页挤掉。
  • 这种替换次序变化，可能让“好不容易留住的常用页”被提前换出，缺页次数反而增加。

FIFO工作流程

假设缓存大小 = 3;访问序列：A B C A D B E

  • A → 缓存：[A]
  • B → 缓存：[A, B]
  • C → 缓存：[A, B, C]（满）
  • A → 命中，FIFO 不改变顺序，还是 [A,B,C]
  • D → 淘汰最早 A → 缓存：[B, C, D]
  • B → 命中，顺序不变
  • E → 淘汰最早 B → 缓存：[C, D, E]
  • 关键点：即使 A 刚被访问过，它依然是最早进的，照样被踢。

FIFO 结构实现

  • 用 队列（Queue） 维护顺序
  • 用 哈希表 / 集合 快速判断是否命中
  • 插入 / 删除都是 O (1)

优缺点

优点

  • 实现最简单
  • 开销极小，不需要记录额外信息
  • 适合按顺序访问、很少重复访问的场景

缺点

  • 不适应热点数据，频繁访问的老数据，照样会被踢掉
  • Belady 异常，有时候增大缓存大小，命中率反而变低（只有 FIFO 会出现）
  • 对实际访问模式不敏感

LRU 缓存技术算法

最近最少使用，它的设计原则借鉴了时间局部性原理，该算法认为如果数据最近被访问过，那么将来被访问的几率也更高，反之亦然。其原理是将数据按照其被访问的时间形成一个有序序列，最久未被使用的数据应该最早被淘汰掉，即当缓存空间被占满时，缓存内最长时间未被使用的数据将被淘汰掉。

潜在问题：淘汰热点数据，如果有个数据在1个小时的前59分钟访问了1万次(可见这是个热点数据),再后一分钟没有访问这个数据，但是有其他的数据访问，就导致了我们这个热点数据被淘汰。

算法流程

为了实现高效的 get（读取）和 put（写入）操作（通常要求时间复杂度为 O(1)），LRU 算法通常采用 “哈希表 + 双向链表” 的组合数据结构。

  • 哈希表 (HashMap)：负责存储 key 到链表节点的映射，实现 O(1) 的快速查找。
  • 双向链表 (Doubly Linked List)：负责维护数据的“使用时序”。链表头部代表“最近使用”，尾部代表“最久未使用”。

重点算法流程：

读取数据部分：

  1. 查找：首先在哈希表中查找 key 是否存在。
  2. 未命中：如果 key 不存在，直接返回一个特定值（如 -1 或 null）。
  3. 命中：如果 key 存在：
    • 通过哈希表找到对应的链表节点。
    • 获取该节点中存储的 value。
    • 关键步骤：将该节点从链表的当前位置移除，并移动到链表的头部。这一步是为了标记该数据为“最近使用”。
    • 返回 value。

写入数据部分：

  1. 查找：首先在哈希表中查找 key 是否已存在。
  2. Key 已存在 (更新操作)：
    • 更新该节点中的 value 为新值。
    • 同样，将该节点移动到链表的头部，标记为“最近使用”。
  3. Key 不存在 (新增操作)：
    • 检查容量：判断当前缓存是否已满（即哈希表/链表的大小是否达到容量上限）。
    • 若已满，执行淘汰：
      • 找到链表尾部的节点（即“最久未使用”的数据）。
      • 从哈希表中删除该尾部节点的 key。
      • 从链表中删除该尾部节点。
    • 插入新数据：
      • 创建一个包含 key 和 value 的新节点。
      • 将新节点插入到链表的头部。
      • 在哈希表中建立 key 到这个新节点的映射。
操作 核心步骤 目的
get(key) 1. 哈希表查找
2. 找到则移动到链表头部		 读取数据并更新其为“最近使用”
put(key, value) 1. 哈希表查找
2. 若存在则更新并移到头部
3. 若不存在则检查容量，必要时淘汰尾部节点，再插入新节点到头部		 写入/更新数据并维护缓存容量和使用时序
