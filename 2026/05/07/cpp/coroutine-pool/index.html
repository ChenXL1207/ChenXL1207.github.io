C++协程池项目

背景介绍

为什么要做协程

你可以把协程想象成“超级轻量级的线程”。

  • 传统线程：由操作系统内核管理。创建、销毁、切换都需要内核介入，开销大（内存占用 MB 级，切换耗时微秒级）。
  • 协程：由用户程序（也就是你的协程库）在用户态自己管理。操作系统根本不知道协程的存在，它只看到一个线程在跑。协程的切换只是修改几个寄存器和栈指针，开销极小（内存占用 KB 级，切换耗时纳秒级）。

协程库的作用就是：

  • 封装底层细节：帮你搞定栈的分配、上下文切换（ucontext / 汇编）。
  • Hook 系统调用：当你调用 read、write、sleep 等阻塞函数时，协程库会拦截它们，把它们变成非阻塞的，并自动调度其他协程去运行，从而不让线程卡住。

协程定义

协程中包含两个关键部分：resume恢复 和 yield暂停

协程是一种执行过程中可以 yield（暂停）和 resume（恢复）的子程序。也可以说，协程就是函数 + 函数运行状态的组合。

怎么理解？普通函数一旦开始执行，就会一直运行到结束，中间不会中断，更不会执行到一半跑去执行别的函数。但协程不同：我们会先为协程绑定一个入口函数，并且可以在函数执行的任意位置暂停，转而去执行其他函数，之后再回到暂停点继续执行。因此说协程是函数与其运行状态的结合——协程会绑定入口函数，并完整记录函数的运行状态。

协程库代码

  • thread：这个模块主要为了弥补协程的缺点，通过多线程 + 多协程的方式，更好地利用多核 CPU 资源。
  • fiber：负责协程的创建、暂停、恢复等核心逻辑，是真正运行任务的单元。
  • scheduler：如果没有这个类，就需要用户手动控制协程的执行与切换，不够灵活也不够智能。
  • ioscheduler：即 IO 调度器，是 scheduler 的 IO 增强版。协程库要用于实际服务器项目，必须能处理文件描述符（fd），否则就只是玩具项目。该类使用 epoll 监听 fd 上的读写事件，事件触发后将协程加入调度器等待执行。
  • timer：服务器通常需要定时器处理定时任务。该模块负责定时器的创建、添加与删除，内部使用最小堆管理超时时间；定时器触发时通过 tickle 信号唤醒 ioscheduler 中的 epoll_wait。
  • hook：只有结合 hook 与 ioscheduler，才能真正实现非阻塞的服务器框架。虽然前面已经实现了协程调度，但如果不修改系统调用行为，就无法在阻塞时自动挂起 / 恢复协程。例如 sleep(1) 仍然会阻塞整个线程，无法体现协程优势。因此通过 hook 替换原始系统调用，增强其逻辑：将 sleep(1) 这类操作转为定时任务，放入 timer 的最小堆中等待超时，之后唤醒 epoll，再将协程交回调度器执行。

生产者-消费者模型

生产者-消费者模型是多线程编程中一个非常经典的并发协作模式。简单来说，它描述的是一类问题：生产数据的线程（生产者）和消费数据的线程（消费者）通过一个共享的缓冲区进行交互。

生产者-消费者模型主要由三个部分组成：

  1. 生产者 (Producer)：负责生成数据或任务，并将其放入共享缓冲区。如果缓冲区已满，生产者必须等待。
  2. 消费者 (Consumer)：负责从共享缓冲区中取出数据或任务并进行处理。如果缓冲区为空，消费者必须等待。
  3. 共享缓冲区 (Shared Buffer)：作为生产者和消费者之间的“中间件”，通常是一个固定大小的队列。它必须保证线程安全，即在同一时间只能有一个线程（生产者或消费者）对其进行操作。

工作原理与同步机制

这个模型的关键在于如何协调生产者和消费者对共享缓冲区的访问。这需要两种同步机制：

  • 互斥 (Mutex)：保证在任一时刻，只有一个线程能访问缓冲区。这就像一个厕所的锁，一次只能有一个人进去。
  • 同步 (Synchronization)：通过条件变量来协调线程间的等待和通知。
    • 缓冲区为空时：消费者线程必须等待。生产者放入数据后，需要通知（notify）等待的消费者。
    • 缓冲区为满时：生产者线程必须等待。消费者取出数据后，需要通知（notify）等待的生产者。

在模型中常用到条件变量方法condition_variable，std::condition_variable（条件变量）的常用方法主要可以分为三大类：等待（Wait）、通知（Notify） 和 唤醒所有（Notify All）。

方法分类 常用方法签名 核心作用
等待 wait(unique_lock<mutex>& lock) 释放锁并阻塞当前线程，直到被通知（需配合 while 循环防虚假唤醒）
等待 wait(lock, Predicate pred) （强烈推荐） 带谓词（条件判断）的等待，自动处理虚假唤醒，等价于 while(!pred) wait(lock)
超时等待 wait_for(lock, rel_time) 带超时时间的等待，超时后无论条件是否满足都会返回
通知 notify_one() 唤醒一个正在等待此条件变量的线程（如果有多个，随机唤醒一个）
通知 notify_all() 唤醒所有正在等待此条件变量的线程
