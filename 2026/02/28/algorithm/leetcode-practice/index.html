二分查找

主要分为三种情况：闭区间、左闭右开、开区间，从中介绍三种写法

  • 闭区间，二分查找第一种写法

    区间的定义这就决定了二分法的代码应该如何写，因为定义target在[left, right]区间，所以有如下两点：（一定要注意【left，right】这个区间，很重要>）

    • while (left <= right) 要使用 <= ，因为left == right是有意义的，所以使用 <=

    • if (nums[middle] > target) right 要赋值为 middle - 1，因为当前这个nums[middle]一定不是target，那么接下来要查找的左区间结束下标位置就是 middle - 1

deque（双端队列）和 queue（队列）都是线性数据结构，但它们的核心区别在于操作的灵活性和适用场景。

数据结构-堆（优先队列）（持续更新）

视频推荐：【从堆的定义到优先队列、堆排序】 10分钟看懂必考的数据结构——堆】https://www.bilibili.com/video/BV1AF411G7cA?vd_source=

堆在逻辑上是一棵完全二叉树，但在物理存储上通常使用数组来实现。这种存储方式非常节省空间，且访问速度快。
堆主要分为两种类型：

  • 大根堆（最大堆）：
    • 规则：父节点的值 ≥ 子节点的值。
    • 特点：堆顶（根节点）是整个堆中最大的元素。
    • 用途：常用于求“最大的K个数”或任务调度（优先级最高的先执行）。
  • 小根堆（最小堆）：
    • 规则：父节点的值 ≤ 子节点的值。
    • 特点：堆顶（根节点）是整个堆中最小的元素。
    • 用途：常用于求“最小的K个数”或Dijkstra最短路径算法。

数组与完全二叉树的映射关系
由于堆是完全二叉树，我们可以通过数组下标直接计算父子节点的位置（假设数组下标从 0 开始）：

节点关系 公式
父节点 (i - 1) / 2 (整数除法)
左孩子 2 * i + 1
右孩子 2 * i + 2

假设我们要删除节点 B：

A -> B -> C

  • 定位：我们需要持有 A 的指针（前驱），因为 A 是连接 B 的关键。
  • 搭桥：执行 A->next = B->next（即 A->next = C）。
  • 此时内存中变成了：A -> C，而 B 孤零零地挂在旁边。
    释放：执行 delete B。

头插法

简单理解：比如链表为 1→2→3。创建一个新的空链表，然后用头插法依次把节点 1,2,3 插到这个新链表的头部，就得到了链表 3→2→1，这正是反转后的链表。

头插法的意思是，把一个节点 node 指向链表头节点（node.next 更新为链表头节点），那么 node 就插在了链表的左侧，新链表的头节点为 node。

对于链表 1→2→3，结合代码来说，顺序为：

  • 第一轮循环结束后，得到链表 1。
  • 第二轮循环结束后，得到链表 2→1。
  • 第三轮循环结束后，得到链表 3→2→1。

自顶向下 DFS（前序遍历）

碰到一个问题：什么时候DFS需要返回值？什么时候不需要返回值

区分这两种写法的核心在于：你的计算逻辑是“自顶向下传递信息”，还是“自底向上汇总信息”。

简单来说：

  • 不需要返回值（void）：通常用于遍历、统计、修改状态。你只关心“走到过哪里”或“找到了什么”，不需要把子节点的结果拿回来做数学运算。
  • 需要返回值（int/bool 等）：通常用于计算高度、求和、判断路径是否存在。父节点必须依赖子节点的计算结果才能得出自己的答案。

第五阶段 网格图

基础知识

在 LeetCode 等算法刷题平台中，二维网格（Grid）类型的题目非常经典。无论是寻找路径、计算连通块（岛屿），还是检测特定形状，它们背后都指向了同一个核心算法：网格图上的深度优先搜索（DFS）。

要写好网格上的 DFS，我们可以类比二叉树的 DFS。二叉树的 DFS 只有两个分支（左子树、右子树），而网格图本质上是一个“四叉树”（或八叉树）。

对于网格中的任意一个格子 (r, c)，它的相邻节点就是它的上下左右四个格子：(r-1, c)、(r+1, c)、(r, c-1)、(r, c+1)。

因此，网格 DFS 的核心要素只有两个：

  1. 访问相邻节点：向四个方向递归。
  2. 判断 Base Case（递归终止条件）：什么时候不能继续往下走？通常是越界或者遇到了障碍物/水。

代码模板

无论题目怎么变，网格图 DFS 的代码骨架是高度固定的。以下是基于 C++ 的通用模板：

  1. 边界与合法性校验（Pruning）
    网格是有边界的，如果不做判断直接递归，会导致数组越界崩溃。通常我们采用**“先污染后治理”**的策略：先无脑向四个方向发起递归，在 DFS 函数的开头统一判断坐标是否合法，不合法直接 return。

  2. 访问标记与防环（Visited / 沉岛思想）
    网格图 DFS 最容易踩的坑就是死循环（比如 A 节点调用 B 节点，B 节点又调用 A 节点）。

  • 常规做法：使用一个额外的 boolean[][] visited 数组记录走过的格子。
  • 进阶做法（沉岛思想）：为了节省空间，直接在原数组上进行修改。比如把走过的陆地 1 改成水 0，或者改成其他标记值 2。这样既起到了防环的作用，又节省了 $O(M \times N)$ 的空间。
  1. 方向控制（固定 vs 动态）
  • 固定方向：像岛屿问题，永远是上下左右四个方向，使用固定的 DIRS 数组即可。
  • 动态方向：有些题目（如迷宫管道），当前格子能走的方向是由格子自身的状态决定的。此时只需将 DIRS 数组替换为根据 grid[r][c] 动态获取的方向列表。

掌握了上面的模板，你只需要修改 DFS 内部的返回值和状态转移方程，就能秒杀以下经典问题：

  1. 连通块计数（如 LeetCode 200. 岛屿数量）：
    不需要返回面积，只要遇到陆地就发起一次 DFS，把整片岛屿“淹没”，然后全局计数器 count++。
  2. 连通块极值（如 LeetCode 695. 岛屿的最大面积）：
    DFS 返回当前连通块的面积，主函数中用一个全局变量 maxArea 不断打擂台取最大值。
  3. 周长计算（如 LeetCode 463. 岛屿的周长）：
    在 DFS 中，如果遇到边界或水，说明这是一条周长边，返回 1；如果遇到已访问的陆地，返回 0；否则继续向四周探索并累加。
  4. 路径回溯（如 LeetCode 79. 单词搜索）：
    需要寻找一条特定路径。此时“沉岛思想”需要升级为回溯：进入 DFS 时标记为已访问，退出 DFS 时必须恢复原状，以便其他路径可以再次使用该格子。

位运算专题（Bit Manipulation）

位运算（Bit Manipulation）是一种通过直接操作整数底层的二进制位来优化算法性能、降低空间复杂度的强大技术。以下是算法中常用位运算技巧的系统性总结，适用于 LeetCode 中大量涉及位运算的题目（如题号 136、191、231、338 等）。

基础判断与数学运算

判断奇偶性

使用 n & 1。若结果为 1 则为奇数，为 0 则为偶数。

快速乘除与取模（2 的幂次）

操作 位运算写法 等价数学运算
乘以 2^k n << k n × 2^k
除以 2^k n >> k n ÷ 2^k（向下取整）
对 2^k 取模 n & ((1 << k) - 1) n % 2^k

判断是否为 2 的幂

利用 2 的幂次方在二进制中只有一个 1 的特性，使用 (n & (n - 1)) == 0 进行判断（注意需保证 n > 0）。

原理：例如 n = 8（二进制 1000），n - 1 = 7（二进制 0111），两者按位与结果为 0。

单比特位操作

操作 写法 说明
检查第 i 位是否为 1 (X & (1 << i)) != 0 或 (X >> i) & 1 == 1 i 从 0 开始计数（最低位为第 0 位）
将第 i 位置为 1 X | (1 << i) 无论该位原来是 0 还是 1，结果都为 1
将第 i 位清零 X & (~(1 << i)) 无论该位原来是 0 还是 1，结果都为 0
翻转第 i 位 X ^ (1 << i) 1 变 0，0 变 1

数据结构优化

位数组（Bit Array）/ 位图（Bitmap）

使用单个二进制位来表示布尔值或整数状态，极大压缩存储空间。例如，用一个 int（32 位）可以同时表示 32 个布尔标志位。

布隆过滤器（Bloom Filter）

一种概率数据结构，利用位运算和多个哈希函数来高效测试元素是否属于某个集合。特点是：可能存在假阳性（误报），但绝不存在假阴性（漏报）。常用于缓存穿透防护、URL 去重等场景。

⚠️ 使用位运算的注意事项

注意事项 说明
负数处理 在进行乘除、取模等移位操作时，负数不能直接套用正数的规则。负数在内存中以补码形式存储，右移时高位补 1（算术右移），需特别注意符号位的影响。
整数溢出 对大数字进行左移操作时（如 1 << 31 在有符号 32 位 int 中），要警惕整数溢出问题。必要时使用 1LL 或 1ULL 来避免。
未定义行为 避免对负数进行位移操作，这在 C/C++ 等语言的早期标准中属于未定义行为（UB）。同时，移位位数超过或等于类型宽度（如对 int 左移 32 位以上）也是未定义行为。
运算符优先级 位运算符的优先级较低且容易混淆，强烈建议多加括号。例如 (n & 1) == 0 不能写成 n & 1 == 0（== 优先级高于 &）。
